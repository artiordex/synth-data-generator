# 코드 주석 작성 규칙

이 문서는 `C:\식약처\work` 저장소에서 직접 작성하는 Python, TypeScript,
TSX 코드의 주석 형식을 통일하기 위한 규칙이다.

## 적용 범위

- 직접 작성한 소스 파일과 테스트 파일에 적용한다.
- `node_modules`, `.venv`, `.uv`, `dist`, 캐시, 빌드 산출물, 외부 생성 파일에는 적용하지 않는다.
- 주석은 코드의 동작을 반복하지 않고 목적, 제약조건, 설계 이유를 설명한다.

## 파일 헤더

모든 직접 작성한 소스 파일의 최상단에 다음 필드를 작성한다.

```text
파일명: 파일명
경로: 저장소 상대경로
목적: 이 파일이 담당하는 기능을 단답식으로 작성함
작성자: 개발팀
작성일: YYYY-MM-DD
수정일: YYYY-MM-DD
```

Python은 `#` 주석 블록, TypeScript와 TSX는 `/** ... */` 블록을 사용한다.
경로에는 개인 PC의 절대경로를 기록하지 않는다. 작성자는 이름 또는 팀명으로
통일하고, 수정일은 실제 코드 동작이나 구조가 변경된 경우에만 갱신한다.

## 함수와 메소드

단순한 함수는 한 줄 주석으로 작성한다.

```ts
// 파일을 업로드함
function uploadFile(file: File) {}
```

외부에서 호출되는 함수, API 서비스, 재사용 컴포넌트에는 상세 설명을 작성한다.
TypeScript와 TSX는 JSDoc 태그를 사용한다.

```ts
/** 작업 단계 목록을 공통 UI로 표시함
 * @param steps 표시할 작업 단계 목록
 * @param activeStep 현재 활성 단계
 * @returns 작업 단계 네비게이션 UI
 */
```

Python은 IDE와 문서화 도구 호환성을 위해 `Args`, `Returns`, `Raises` 형식의
docstring을 사용한다.

```python
def get_job(job_id: str) -> Job:
    """작업 정보를 조회함

    Args:
        job_id: 조회할 작업 식별자
    Returns:
        조회된 작업 정보
    Raises:
        FileNotFoundError: 작업이 존재하지 않는 경우
    """
```

## 복잡한 로직과 태그

복잡한 조건, 보안 검증, 파일 형식 보존, 재시도·취소 처리에는 필요한 이유를
짧게 작성한다. 단순한 변수 선언이나 반복문에는 주석을 달지 않는다.

허용 태그는 `TODO`, `FIXME`, `NOTE`, `WARN`, `SECURITY`로 제한한다.
문장 종결은 `~함`, `~검증함`, `~저장함`, `~표시함`처럼 단답식으로 통일한다.
