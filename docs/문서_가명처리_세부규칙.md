# 문서 가명처리 세부 규칙

규칙 버전: `1.0.0`

적용 범위: 원본 편집 방식 PDF/HWP/HWPX의 치환 후보 생성과 수동 입력 검증.
정형 데이터의 합성 생성, CSV 내보내기 및 일반 텍스트 재작성에는 이 정책을 자동 적용하지 않는다.

## 1. 데이터 표현을 구분한다

1. 원문: 파일에서 읽은 문자열. 절대로 정규화 결과로 덮어쓰지 않는다.
2. 탐지용 문자열: 한 문자씩 대응하는 정규화 사본. 정규식 인덱스를 원문에 그대로 적용할 수 있어야 한다.
3. 대체값: 탐지된 개인정보 범위에서만 작성한다.
4. 출력값: 원문의 공백·기호를 복원한 대체값. 원문 위치에 삽입하기 전에 형식을 검증한다.

구현: `privacy/text_format_rules.py`의 `detection_view`, `restore_format`, `validate_format`.
후보 생성과 수동 치환 검증은 모두 위 모듈을 호출한다.

## 2. 공백과 간격

| 대상 | 탐지용 처리 | 출력·검증 규칙 |
|---|---|---|
| 일반 공백 U+0020 | 그대로 | 개수와 문자 인덱스 보존 |
| 연속 공백 | 합치지 않음 | 두 칸을 한 칸으로 줄이지 않음 |
| 탭 U+0009 | 공백 한 문자로 대응 | 탭 원형 복원; 공백으로 바꾸면 거부 |
| NBSP U+00A0 | 공백 한 문자로 대응 | NBSP 원형 복원 |
| 전각 공백 U+3000 | 공백 한 문자로 대응 | 전각 공백 원형 복원 |
| LF / CR / CRLF | 원형 유지 | 현재 네이티브 치환 요청은 줄바꿈 포함 항목을 거부 |
| 기타 Unicode 공백 | 공백 한 문자로 대응 | 원래 코드 포인트와 위치 복원 |
| 제로폭 문자·방향 제어문자 | 삭제하지 않음 | 원문 위치 유지; 새로 삽입 금지 |

문자열 공백 보존과 시각적인 자간 보존은 다르다. PDF의 대체 글꼴 폭이 원본과 다르면
치환 영역 내부의 자간·글자 크기는 달라질 수 있다. 현재는 영역 밖 픽셀과 텍스트 좌표를 검증한다.
글리프별 자간까지 동일하다는 보장은 하지 않는다.

## 3. 기호와 문자 폭

- 하이픈 `-`, `‐`, `‑`, `‒`, `–`, `−`, `－`은 탐지할 때만 `-`로 대응한다.
- 콜론·괄호 등 전각 문자는 한 글자로 변환되는 경우에만 탐지용 NFKC를 적용한다.
- 원문의 괄호, 대괄호, 슬래시, 역슬래시, 쉼표, 마침표, 가운뎃점, 밑줄, @, 별표를 복원한다.
- 원문에 있던 기호는 삭제·이동·종류 변경을 허용하지 않는다.
- 숫자의 전각·반각을 유지한다. `０１０－１２３４－５６７８`은 동일한 전각 형식으로 반환한다.
- ASCII 영문은 대문자·소문자 위치를 유지한다.
- 완성형 한글은 완성형 한글 또는 이름 마스킹용 `*`로 바꿀 수 있다.
- 문자 위치에 새 공백·제어문자·기호를 삽입하지 않는다. 마스킹용 `*`, `＊`만 예외이다.
- NFKC 결과가 여러 글자로 늘어나는 합자 등은 정규화하지 않는다.
- 분해형 한글 자모를 결합하지 않는다. 자동 탐지가 보장되는 범위는 완성형 한글이다.

## 4. 개인정보 유형별 규칙

| 유형 | 탐지 근거 | 현행 대체 규칙 | 검토 사항 |
|---|---|---|---|
| 한글 이름 | 성명·예금주·고객 등 문맥 | 현재 이름 마스킹 방식과 길이 유지 | 동명이 일반 명사로 쓰이는 경우 자동 제안 제한 |
| 영문 이름 | 성명 한글/영문 필드 | 영문 대소문자·공백 위치 유지 | 로마자 이름의 자연스러움은 보장하지 않음 |
| 전화번호 | 국내 번호 형태 | 지역·휴대전화 접두부 유지, 나머지 숫자 치환 | 실제 개통 여부 보장 안 함 |
| 이메일 | local@domain 형태 | local 부분 치환, 기호·도메인 유지 | 도메인이 민감하면 별도 정책 필요 |
| 생년월일 | 생년월일/출생 문맥 | 현재 고정 가상 날짜 사용; 구분자·년월일 유지 | 분석용 분포 보존 목적 아님 |
| 계좌번호 | 은행명 뒤 번호 문맥 | 숫자 치환, 길이와 하이픈 유지 | 금융기관별 체크섬 검증 없음 |
| 여권·면허·보험번호 | 필드명과 번호 패턴 | 숫자 치환, 접두문자·구분자 유지 | 발급 가능한 유효 번호 보장 안 함 |
| 사용자 ID | 아이디 필드 | 문자 종류·구분자 유지 | 실제 계정과의 비충돌 보장 안 함 |
| 주소 | 행정구역·도로명·번지 형태 | 길이·공백·기호 유지하며 치환 | 현재 자연스러운 가상 주소 생성은 미구현 |

기관명은 인명으로 바꾸지 않는다. 일반 명사라는 이유만으로 개인정보로 분류하지 않는다.
가명값이 그럴듯한 실제 번호 또는 주소여야 한다는 규칙과, 원문 식별값을 제거한다는 규칙은 별개이다.
현재 문서 엔진은 길이와 구조 보존을 우선한다.

## 5. 수동 수정과 오류

| 오류 코드 | 거부 조건 |
|---|---|
| FORMAT_LENGTH | 원문과 대체값 길이 불일치 |
| FORMAT_LITERAL | 원문 공백·기호·제어문자 변경 |
| FORMAT_INSERTION | 허용되지 않은 기호·공백 삽입 |
| FORMAT_DIGIT | 숫자 위치를 다른 종류의 문자로 변경 |
| FORMAT_WIDTH | 전각/반각 숫자 형식 변경 |
| FORMAT_CASE | 영문 대소문자 형식 변경 |
| FORMAT_HANGUL | 한글 위치를 허용되지 않은 문자로 변경 |

추가로 빈 값, 원문과 같은 값, 중복 원문, 겹치는 원문, 다른 원문이 포함된 대체값을 거부한다.
현재 API의 네이티브 치환은 한 줄씩 처리한다. 공백 규칙 모듈이 CRLF를 보존할 수 있다는 것은
여러 줄을 잇는 개인정보의 문서 좌표 탐지가 구현됐다는 뜻이 아니다.

## 6. 문서 서식 검증

- 원본의 페이지 수와 크기가 같아야 한다.
- 글꼴·크기·색상이 다른 구간은 각각의 기존 스타일로 나누어 처리한다.
- 해당 폰트에 글리프가 없으면 대체 글꼴이 사용될 수 있다.
- 치환 영역을 넘는 대체 문자열은 현재 엔진에서 크기를 조정한다.
- 치환 영역 밖 픽셀이나 원문 텍스트 좌표가 달라지면 결과를 차단한다.
- 선택 원문의 텍스트 추출 및 검사 가능한 내부 객체 잔존을 검사한다.
- 결과 보고서에 적용된 문자열 규칙 버전을 기록한다.

## 7. 후속 구현이 필요한 경계

1. 줄바꿈 주소: 같은 문단·셀임을 확인한 후 원문 위치 매핑을 유지하며 여러 줄로 치환해야 한다.
2. 글자 사이 공백 이름: `홍 길 동`을 인명 필드 또는 좌표 문맥에서 확인해야 하며 문서 전체 공백 제거는 금지한다.
3. 스캔 PDF: OCR 좌표와 이미지 편집·잔존 검증이 별도로 필요하다.
4. HWP/HWPX: 표·문단 속성의 완전 일치 검증은 네이티브 렌더링 환경과 함께 확장해야 한다.
5. 자연스러운 주소: 같은 길이의 행정구역·도로명·건물명 사전을 사용하되 실제 주소 충돌 정책이 필요하다.
6. 정형 데이터: 필드 타입·결측값·관계키 규칙은 이 문서 규칙과 별도로 버전 관리해야 한다.
