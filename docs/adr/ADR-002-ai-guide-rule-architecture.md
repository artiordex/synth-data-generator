# ADR-002: AI 가이드 규칙 기반 아키텍처 및 2-Track·대용량 처리 지침

- 상태: Accepted

- 작성자: 시스템 아키텍처팀
- 적용 범위: `AI_READY_GUIDE_SPEC.md`, `AiRuleGuideStudio.tsx`, 백엔드 `ai_guide.py` 및 규칙 생성 엔진

## 1. 배경 (Context)

공공데이터를 AI 모델이 즉시 활용할 수 있도록 지원하는 AI 친화 가이드(AI-Ready Guide)는 단순한 문서 요약이 아니라, 데이터셋의 기계 판독성, 데이터 스키마, 결측치 및 품질, 라이선스, AI 활용 적합성을 종합적으로 정의하는 표준 명세서이다.

단일한 거대 LLM 프롬프트에 모든 가이드 작성을 일임할 경우 다음과 같은 중대한 결함이 발생한다:
1. **환각(Hallucination) 및 임의 추정**: 원천 데이터에 없는 가상의 API URL, 가짜 컬럼 설명, 임의의 라이선스나 담당자 정보를 그럴듯하게 날조함.
2. **포맷별 특성 왜곡**: 행/열 기반의 표 형식 파일데이터(CSV/XLSX)와 중첩 계층형 API 응답(JSON/XML)의 본질적 차이를 무시하고 획일화함.
3. **대용량 데이터 한계**: 수백 MB~수 GB의 대용량 데이터를 처리하지 못하거나 임의로 잘라내어 레코드 구문이 파괴됨.

따라서 최상위 원칙으로서 **2-Track 처리 분류**, **추측 금지(No Hallucination) 원칙**, 그리고 **대용량 데이터 최적화 지침**을 명문화하는 규칙 기반 아키텍처가 필요하다.

## 3. 결정 사항 (Decisions)

### 3.1 2-Track 처리 아키텍처 (파일데이터 vs API데이터)

입력 데이터의 형식적·의미적 특성에 따라 2가지 독립적인 파이프라인으로 분기하여 처리한다.

```text
               ┌── [CSV / TSV / XLSX] ──▶ Track 1: 파일데이터 가이드 (File-Based Guide)
입력 포맷 판정 ─┤
               └── [JSON / XML / JSON-LD] ──▶ Track 2: API데이터 가이드 (API-Payload Guide)
```

#### Track 1: AI 친화 파일데이터 가이드 (File-Based Dataset Guide)
- **적용 대상**: CSV, TSV, XLSX
- **핵심 분석 초점**:
  - 2차원 표(Tabular) 구조 분석, 헤더 정합성, 컬럼별 데이터 타입 및 포맷 판정.
  - 결측치(Null/Empty), 이상치, 중복 레코드, 후보키(Candidate Key) 검출.
  - 파일 인코딩(UTF-8, CP949), 구분자, 총 레코드 수 및 바이트 크기 프로파일링.
- **가이드 반영 사항**: 일괄 배치 학습(Batch Training) 적합성, 데이터 분할(Train/Val/Test) 권고, 정형 전처리 파이프라인 안내.

#### Track 2: AI 친화 API데이터 가이드 (API-Payload Dataset Guide)
- **적용 대상**: JSON, JSON-LD 1.1, XML
- **핵심 분석 초점**:
  - 중첩 계층 경로(JSON Pointer / XPath), 배열 합집합 타입, 객체 컨테이너 구조 보존.
  - 응답 봉투(Envelope: `header`, `body`, `items`, `record` 등)와 실제 비즈니스 페이로드의 분리.
  - XML 네임스페이스(Namespace URI 및 QName) 식별, 속성(`@attributes`)과 요소 분리.
- **가이드 반영 사항**: 실시간 API 호출 연계, 엔드포인트 계약(Contract) 검토, JSON-LD 시맨틱 웹 및 온톨로지 연동 방안 안내.

### 3.2 사실 확인 및 추측 금지 원칙 (No Hallucination & Fact-Checking)

1. **원천 관측치와 추정의 엄격한 분리**:
   - 데이터 값에서 직접 관측·계산된 사실(행 수, 컬럼 수, 관측 타입, 결측률 등)만 확정값으로 기록한다.
   - 데이터 값만으로 확정할 수 없는 업무적 필수 여부, DB 제약조건(PK/FK), 법적 라이선스는 AI가 임의로 단정하지 않는다.
2. **미확인 API 계약의 `REVIEW_REQUIRED` 격리**:
   - JSON 응답 페이로드 하나만 보고 엔드포인트 URL, HTTP Method(GET/POST), 인증 방식(API Key/OAuth), 호출 한도를 추측하여 확정하지 않는다.
   - 확인되지 않은 계약 정보는 반드시 `status: REVIEW_REQUIRED`로 마킹하고 사람(담당자) 검토 항목으로 도출한다.
3. **AI 설명 생성의 안전 경계**:
   - LLM은 데이터 구조와 컬럼명에 대한 "이해 보조용 설명 초안(Draft Description)" 및 "AI 활용 시나리오"를 작성하는 용도로만 한정한다.
   - LLM이 산출한 설명 텍스트는 수치 데이터를 수정하거나 상위 스키마를 변경할 수 없다.

---

### 3.3 대용량 데이터(Large-Scale Dataset) 파이프라인 최적화 지침

수십 MB 이상의 대용량 공공데이터 분석 시 시스템 안정성과 대표성을 보장하기 위해 다음 원칙을 강제한다.

```text
[대용량 원천 데이터] ──▶ [레코드 경계 보존] ──▶ [안전 청크 샘플링 (1,000~10,000행)]
                                                         │
                                                         ▼
                                             [결정적 통계 & 스키마 도출]
                                                         │
                                                         ▼
                                           [열기반 Parquet 전환 가이드 권고]
```

1. **레코드 경계 보존 (Record Boundary Integrity)**:
   - 텍스트를 바이트 단위로 임의 절단(Slice)하여 파싱하지 않는다. 반드시 유효한 레코드(CSV 라인, XML 닫는 태그, JSON 배열 객체) 단위로 분할 처리한다.
2. **청크 기반 통계 샘플링**:
   - 브라우저 및 API 서버의 메모리 초과를 방지하기 위해 대표 표본(Sample)을 추출하여 분석하되, 가이드 문서에 **"분석 대상: 샘플 N건 (전체 데이터셋 N건 중)"**임을 명확히 표시한다.
3. **고성능 AI 저장 포맷 전환 권고**:
   - 대용량 파일데이터에 대해서는 CSV의 I/O 병목 및 타입 손실을 극복하기 위해 Apache Parquet 등 압축 열지향(Columnar) 포맷으로의 변환 가이드라인을 필수로 제공한다.

## 5. 결과 (Consequences)

### 긍정적 효과
- **데이터 성격별 맞춤형 가이드 생성**: 파일데이터와 API데이터의 고유한 특성을 살린 정밀한 문서가 생성됨.
- **신뢰성 및 법적 무결성**: AI의 자의적 추측이나 가짜 정보 생성을 원천 차단하여 공공기관 제출 및 대국민 서비스용으로 즉시 활용 가능함.
- **대용량 확장성**: 수 기가바이트의 대형 공공데이터셋도 메모리 장애 없이 안전하고 일관되게 분석 가능함.

### 관리 시 주의사항
- 신규 포맷(예: GeoJSON, Parquet 원본 등)이 도입될 경우 Track 1 또는 Track 2와의 호환성을 검토하여 분류 체계를 확장해야 한다.
