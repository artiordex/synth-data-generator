# ADR-004: 데이터 유형(Trait) 자동 판별 및 적응형 6대 품질분석 체계

- 상태: Accepted
- 결정일: 2026-09-16
- 작성자: 시스템 아키텍처팀
- 적용 범위: 데이터 프로파일링 엔진, 품질 평가 알고리즘, AI 친화도 점수(0~100점) 산출 모듈

---

## 1. 배경 (Context)

공공데이터는 단순한 정형 표(XLSX/CSV)뿐만 아니라 계층형 API 응답(JSON/XML), 시계열 센서 로그, 비정형 텍스트, 이미지 메타데이터 등 다양한 형태로 존재한다.

모든 데이터셋에 획일화된 단일 검사표를 강제 적용할 경우 다음과 같은 문제가 발생한다:
1. **적용 불가 지표의 강제**: 텍스트나 API 계층 데이터에 RDB 형태의 기본키(PK)나 결측률을 억지로 요구하여 무의미한 오류를 양산함.
2. **핵심 품질 요건 누락**: 시계열 데이터에서 시간 연속성 누락이나 데이터 누수(Data Leakage)를 감지하지 못하거나, API 페이로드에서 배열 합집합 타입의 불일치를 놓침.
3. **단순 파싱과 실질 품질의 혼동**: 구문 오류가 없다고 해서 AI 학습에 적합하다고 잘못 판정함.

따라서 파일 확장자만을 기준으로 삼지 않고, 데이터의 실제 구조와 속성을 분석하여 **데이터 특성(Trait)을 다중 부여**하고, 이에 맞춘 **적응형 품질 분석(Adaptive Quality Analysis)**을 수행해야 한다.

## 3. 결정 사항 (Decisions)

### 3.1 입력 형식(Format)과 데이터 특성(Trait)의 분리 판정

물리적 파일 형식(Format)과 논리적 의미 특성(Trait)을 분리하여 판별하며, 하나의 데이터셋에 **복수의 Trait**를 부여할 수 있다.

```text
[입력 데이터] ──▶ 1차: 물리 포맷 식별 (CSV, TSV, XLSX, JSON, XML, JSON-LD)
              │
              └──▶ 2차: 논리 특성(Trait) 다중 부여
                      ├─ STRUCTURED_TABULAR   (2차원 행·열 구조)
                      ├─ API_PAYLOAD          (응답 헤더/바디 계층)
                      ├─ TIME_SERIES          (시간 흐름 및 주기성)
                      ├─ NESTED_HIERARCHICAL  (중첩 객체 및 이종 배열)
                      ├─ TEXT_HEAVY           (긴 서술형 비정형 텍스트)
                      ├─ IMAGE_REFERENCE      (이미지 URL/파일명 포함)
                      └─ LARGE_DATASET        (대용량 분할 처리 대상)
```

- **예시 1**: 날짜 컬럼과 수치 컬럼이 포함된 CSV 파일
  - `Format`: `CSV`
  - `Traits`: `STRUCTURED_TABULAR` + `TIME_SERIES`
- **예시 2**: 공공병원 위치 및 사진 링크를 담은 공공 API JSON 응답
  - `Format`: `JSON`
  - `Traits`: `API_PAYLOAD` + `NESTED_HIERARCHICAL` + `IMAGE_REFERENCE`

### 3.2 공통 6대 품질지표의 정량적 프로파일링 공식

[REF-02]의 공통 6대 품질 축을 기반으로 결정적 알고리즘을 통해 점수를 계산한다.

```text
┌─────────────────┬────────────────────────────────────────────────────────┐
│ 품질 지표       │ 측정 내용 및 정량화 방식                               │
├─────────────────┼────────────────────────────────────────────────────────┤
│ 1. 완전성       │ 필수 컬럼 누락 여부, 결측치(Null/Empty/NA) 비율        │
│ (Completeness)  │ 공식: (1 - (결측 셀 수 / 전체 셀 수)) × 100            │
├─────────────────┼────────────────────────────────────────────────────────┤
│ 2. 유효성       │ 선언/관측된 데이터 타입 및 패턴(정규식, 날짜) 부합율   │
│ (Validity)      │ 공식: (유효 형식 레코드 수 / 전체 레코드 수) × 100     │
├─────────────────┼────────────────────────────────────────────────────────┤
│ 3. 일관성       │ 컬럼 간 논리적 모순, 헤더-데이터 컬럼 수 일치 여부     │
│ (Consistency)   │ 예: 시작일시 <= 종료일시, 최저가 <= 최고가 검증        │
├─────────────────┼────────────────────────────────────────────────────────┤
│ 4. 정확성       │ 이상치(Outlier, 3-Sigma/IQR), 유효 도메인 범위 부합율  │
│ (Accuracy)      │ 공식: (도메인 정상치 레코드 수 / 총 레코드 수) × 100   │
├─────────────────┼────────────────────────────────────────────────────────┤
│ 5. 유일성       │ 중복 레코드(Duplicate Rows) 비율 및 후보키 고유율      │
│ (Uniqueness)    │ 공식: (고유 레코드 수 / 총 레코드 수) × 100            │
├─────────────────┼────────────────────────────────────────────────────────┤
│ 6. 적시성       │ 데이터의 최신성(기록 기준시점 vs 현재시점), 갱신 주기  │
│ (Timeliness)    │ 기관 제공 메타데이터의 최종 갱신일자 기반 산출         │
└─────────────────┴────────────────────────────────────────────────────────┘
```

### 3.3 정량 검사와 정성 검사의 엄격한 역할 분리

1. **정량 검사 (Deterministic Program Verification)**:
   - **수행 주체**: 백엔드 분석 파이프라인 (파이썬 알고리즘).
   - **대상**: 결측치 수, 중복 행 수, 타입 위반 건수, 헤더 수, 바이트 크기, 최소/최대값 등.
   - **원칙**: 수학적으로 완전히 재현 가능해야 하며, LLM의 추론에 의존하지 않는다.
2. **정성 검사 (AI Semantic Analysis & Human Review)**:
   - **수행 주체**: LLM 모델 (설명 초안) 및 업무 담당자 (최종 확인).
   - **대상**: 데이터의 대표성, 사회적 편향(Bias) 가능성, AI 활용 시 주의사항, 도메인 적합성.
   - **원칙**: AI는 "검토 의견 초안"을 제시할 뿐이며, 공식 품질 점수를 임의로 왜곡하거나 조작할 수 없다.

### 3.4 데이터 Trait별 조건부 심층 품질 규칙

기본 6대 품질축 외에 감지된 Trait에 따라 다음 특화 검사를 조건부로 추가 활성화한다.

#### 1. `TIME_SERIES` (시계열 데이터)
- 시간 축 필드의 단조 증가(Monotonic Increasing) 여부 확인.
- 측정 주기(간격)의 규칙성 및 누락된 시점(Time Gap) 탐지.
- 학습용(Train)/검증용(Validation) 분할 시 미래 데이터 누수(Data Leakage) 경고.

#### 2. `API_PAYLOAD` 및 `NESTED_HIERARCHICAL` (API 및 중첩 계층 데이터)
- 동일 경로 내 이종 타입(Heterogeneous Types: 예: `string | integer`) 출현율 검출.
- 배열 내부 필수 속성의 누락률 및 배열 크기 분포(Min/Max/Avg) 분석.
- 응답 봉투(Envelope) 제거 후 순수 데이터 노드의 품질 집중 분석.

#### 3. `TEXT_HEAVY` (서술형 비정형 텍스트)
- 평균 문자열 길이, 인코딩 깨짐(Mojibake), 특수문자 이상 빈도 검출.
- [REF-04] 생성형 AI 가이드에 따른 개인정보(주민번호, 전화번호, 이메일 등) 마스킹 필요성 진단.

## 4. 결과 (Consequences)

### 긍정적 효과
- **품질 진단의 객관성 및 신뢰도 극대화**: 정부 공인 AI 데이터 품질 가이드라인([REF-02])을 100% 수용하여 공공기관 및 기업이 납득할 수 있는 수치 근거 제시.
- **불필요한 품질 경고 제거**: 포맷과 특성에 맞지 않는 억지 검사를 배제하고, 시계열이나 API 응답에 꼭 필요한 맞춤형 품질 가이드를 제공함.
- **AI 안전성 확보**: [REF-04]를 준수하여 환각이나 편향 위험 요소를 선제적으로 경고함.

### 관리 시 주의사항
- 정량 분석 점수(AI 친화도 점수)는 알고리즘 산출 결과이며, 기관의 데이터 업무 적합성을 보증하는 법적 면책 기준은 아님을 가이드 문서에 명시해야 한다.

## 5. 수용 기준 (Acceptance Criteria)

- [x] 입력 데이터의 형식(Format)과 특성(Trait)이 독립적으로 판정됨.
- [x] 공통 6대 품질지표(완전성, 정확성, 유효성, 일관성, 적시성, 유일성)가 정량 수식으로 계산됨.
- [x] 정량 검사(코드 계산)와 정성 검사(AI 설명 초안)가 시스템상에서 명확히 분리됨.
- [x] 시계열 및 API 계층 데이터에 대한 조건부 특화 검사 규칙이 적용됨.
- [x] [REF-02], [REF-04], [REF-05]가 품질 진단의 공식 근거로 명시됨.
