# ADR-005: HWPX·JSON·XML·JSON-LD 다중 포맷 동시 생성 및 출력 일관성 보장

- 상태: Accepted
- 결정일: 2026-09-16
- 작성자: 시스템 아키텍처팀
- 적용 범위: HWPX 문서 변환기, 기계 판독형 메타데이터 렌더러, 패키징 및 내보내기 파이프라인

---

## 1. 배경 (Context)

공공데이터의 AI 친화적 관리를 달성하기 위해서는 두 가지 상충되는 사용자의 요구사항을 동시에 만족해야 한다:
1. **사람(행정가·심의위원)을 위한 서식**: 결재, 심의, 보고, 보존을 위해 대한민국 공공 표준 문서 규격인 **HWPX 공문서** 양식의 완성도 높은 보고서가 필요함.
2. **기계(AI 모델·데이터 파이프라인)를 위한 구조화 포맷**: MLOps 파이프라인 연계, 공공데이터포털 카탈로그 등록, 시맨틱 웹 상호운용성을 위해 **JSON, XML, JSON-LD** 기계 판독형 메타데이터가 필요함.

과거에는 HWPX 문서를 먼저 수작업으로 작성한 뒤 이를 다시 파싱하여 JSON을 만들거나, 반대로 JSON을 HWPX로 대충 변환하면서 표 레이아웃이 깨지고 수치 정보가 어긋나는 심각한 불일치가 발생했다.

따라서 확정된 **단일 Canonical Metadata**로부터 사람용 HWPX 공문서와 기계용 구조화 메타데이터를 **단일 파이프라인에서 동시 생성하고 상호 일관성을 보장**하는 출력 아키텍처가 필요하다.

## 3. 결정 사항 (Decisions)

### 3.1 다중 포맷 렌더링 아키텍처

모든 출력 렌더러는 오직 확정된 `Canonical Metadata`만을 입력으로 받아 실행되며, 원천 데이터에 대한 재분석이나 독자적 수치 산출을 엄격히 금지한다.

```text
               [확정된 Canonical Metadata Model]
                               │
       ┌───────────────────────┼───────────────────────┐
       ▼                       ▼                       ▼
 [HWPX 렌더러]          [JSON / JSON-LD 렌더러]      [XML 렌더러]
       │                       │                       │
       ├─ 정부 표준 표/글꼴    ├─ DCAT-AP-KR 스키마    ├─ 공공연계 스키마
       ├─ 가로/세로 A4 규격    ├─ W3C JSON-LD 1.1      ├─ 엔트리 키 인코딩
       └─ 프리셋 서식 바인딩   └─ 기계 판독형 속성     └─ XML 무결성 검증
       │                       │                       │
       └───────────────────────┼───────────────────────┘
                               ▼
            [출력 간 교차 검증 (Cross-Validation)]
                               │
                               ▼
             [ZIP 통합 배포 패키지 산출물]
```

---

### 3.2 HWPX 공문서 표현형 표준화

HWPX는 사람이 읽고 공식 보고서로 검토·제출하기 위한 **최종 표현형(Presentation Format)**으로 취급한다.

1. **정부 표준 A4 규격 및 프리셋 지원**:
   - 행정안전부·NIA 공공 표준 서식, 기획재정부, 식약처 표준 등 사전 검증된 HWPX 스타일 프리셋을 제공한다.
   - 용지 여백(상·하·좌·우 20mm), 줄 간격(160%), 헤더 배경색 및 괘선(Border) 스타일을 자동으로 엄격 적용한다.
2. **템플릿 데이터 바인딩 원칙**:
   - 특정 사례(예: 태양광 발전소 샘플)의 컬럼명이나 통계치를 템플릿 코드에 하드코딩하지 않는다.
   - 모든 텍스트, 표 셀, 통계 수치는 Canonical Metadata의 바인딩 태그(`{{DATASET_TITLE}}`, `{{FIELD_LIST}}` 등)를 통해 동적으로 주입된다.
3. **표준 12대 가이드 목차 체계**:
   [REF-01] 표준 가이드라인에 부합하는 정규 목차를 구성한다.
   ```text
   Ⅰ. 데이터셋 개요 (명칭, 목적, 범주, 생성일자)
   Ⅱ. 데이터셋 구조 및 스키마 (행/열 수, 경로, 타입, 결측률)
   Ⅲ. 데이터 사전 (Data Dictionary: 표준 컬럼명, 설명, 예시값)
   Ⅳ. 데이터 수집 및 계보 메타데이터 (출처, 변경이력)
   Ⅴ. 공통 6대 품질진단 결과 (완전성, 유효성, 일관성 등)
   Ⅵ. AI 친화도 평가 및 적합성 체크리스트
   Ⅶ. 대용량 데이터 처리 및 파이프라인 가이드 (청크 분할, Parquet 권고)
   Ⅷ. AI 활용 시나리오 및 추천 알고리즘
   Ⅸ. 데이터 한계 및 이용 시 유의사항 (편향성, 결측 보정 여부)
   Ⅹ. 라이선스 및 법적·윤리적 검토 사항 (공공누리, 개인정보 비식별)
   ```

---

### 3.3 기계 판독형 포맷 (JSON, XML, JSON-LD) 표준 명세

1. **`metadata.json`**:
   - Canonical Metadata의 전체 계층 구조를 직렬화한 표준 JSON.
   - API 연계 및 자동화 파이프라인에서 가장 가볍고 빠르게 파싱 가능함.
2. **`metadata.jsonld`**:
   - [REF-07] DCAT-AP-KR 표준 네임스페이스(`@context`: `dct:`, `dcat:`, `dqv:`, `xsd:`)를 적용한 W3C 시맨틱 웹 표준 포맷.
   - 데이터 카탈로그 간 글로벌 연계 및 온톨로지 지식그래프 구축 지원.
3. **`metadata.xml`**:
   - 범정부 행정 정보 연계 및 레거시 공공 시스템을 위한 구조화 XML.
   - XML 스키마 무결성을 보장하며, 특수문자 및 따옴표에 대한 완벽한 XML 엔티티 이스케이프 처리.

---

### 3.4 출력 간 교차 검증 (Cross-Validation) 및 검토본 표시

1. **자동 교차 검증 파이프라인**:
   - HWPX, JSON, XML이 생성된 직후, 각 산출물에 포함된 **핵심 지표(총 레코드 수, 총 컬럼 수, 데이터셋 명칭, 결측 셀 수)**를 역추출하여 Canonical Metadata와 100% 일치하는지 자동 검증한다.
2. **`REVIEW_REQUIRED` 잔여 시 검토본(Draft) 명시**:
   - 담당자의 승인이 필요한 미확인 항목(라이선스, 법령, API 계약 등)이 남아 있는 상태에서 생성된 문서는 HWPX 표지 및 본문 상단에 **`[임시 검토본 - 기관 공식 확인 필요]`** 표식을 강제 인쇄한다.
   - JSON/XML 메타데이터에도 `review_status: "INCOMPLETE_REVIEW"` 플래그를 삽입하여 미완성 가이드가 공인 배포본으로 오용되는 것을 방지한다.

## 4. 최종 배포 패키지 구성 (ZIP Package)

사용자가 '전체 패키지 다운로드'를 요청할 경우 다음 구조의 표준 압축 파일을 제공한다:

```text
[데이터셋명]_AI친화_가이드_패키지.zip
 ├─ [데이터셋명]_AI친화_가이드_공문서.hwpx     (공식 제출 및 행정 보고용)
 ├─ metadata.json                             (기계 판독형 전체 메타데이터)
 ├─ metadata.jsonld                           (DCAT-AP-KR 시맨틱 메타데이터)
 ├─ metadata.xml                              (행정 연계용 구조화 XML)
 ├─ data-dictionary.json                      (독립 데이터 사전 명세)
 ├─ quality-report.json                       (6대 품질 지표 상세 진단서)
 └─ README.md                                 (가이드 패키지 활용 안내)
```

## 5. 결과 (Consequences)

### 긍정적 효과
- **행정 보고와 AI 파이프라인의 완벽한 융합**: HWPX 공문서와 JSON-LD 시맨틱 데이터를 버튼 하나로 오차 없이 동시 확보함.
- **포맷 간 불일치 원천 제거**: 단일 Canonical Metadata를 통해서만 렌더링되므로 보고서와 시스템 데이터 간 수치 불일치 위험 0%.
- **공공데이터 표준 준수**: [REF-01], [REF-07]에 정의된 국가 표준 규격을 완벽히 충족하여 공공데이터포털 개방 평가 우수 등급 확보 가능.

### 관리 시 주의사항
- HWPX 렌더러가 생성하는 바이너리 구조가 한글과컴퓨터 최신 사양(HWPX 1.0)에 맞게 올바른 XML 네임스페이스와 압축 표준을 준수하는지 주기적으로 정합성 테스트를 수행해야 한다.

- [x] `REVIEW_REQUIRED` 잔여 시 문서에 '검토본' 경고 표식이 적용됨.
