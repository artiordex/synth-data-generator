# 기능 개선 작업 목록

검토일: 2026-09-08. 현재 소스를 기준으로 작성한 작업 계획이며, 아래 기능 수정이나 신규 기능이 완료되었다는 의미는 아니다.

### 1차 수정 반영

- 공통 다운로드 API에 출력 폴더 경계 검증을 추가했다. SPA 파일 반환과 설문 다운로드에도 경계 검증을 적용했다.
- 설문 개별 파일 다운로드는 완료된 작업만 허용한다. 사용자/부서 소유권 검증과 산출물 ID 방식은 아직 미구현이다.
- 설문 평가서와 화면의 고정 PASS, 기본 점수, 심의 적격 문구를 제거했다. 실제 JSD 기반 품질과 미측정 상태를 사용한다.
- 적용 가능한 분기 규칙이 없으면 점수와 통과 여부를 null로 반환한다.
- 설문 결합, 미응답 학습, 작업 큐, 인증/인가 등 나머지 항목은 후속 작업이다. 기존 생성 파일은 자동 재작성하지 않는다.

노이즈 추가나 k-익명성 지표만으로 전체 개인정보 보호 또는 심의 적격성을 보장한다고 표시하지 않는다.

## 2. 기존 기능 구조 개선 (refactor)

### 작업 실행과 이력 통합

- 일반, 배치, 설문, 관계형, 시계열 생성에 공통 작업 ID와 상태 모델을 적용한다.
- 라우터는 요청 검증과 서비스 호출만 담당한다. 학습, 파일 저장, ZIP 작성은 서비스와 엔진으로 옮긴다.
- 메모리 `SURVEY_JOBS`와 별도 상태 폴링을 공통 DB 이력으로 통합한다.
- 알고리즘은 별도 구현을 유지하되 공통 결과 객체에 데이터, 평가, 산출물, 적용 옵션을 담는다.
- 완료 기준: 재시작 후 상태 확인, 실패 전달, 취소, 다운로드, 보관 정책을 모든 생성 방식에서 동일하게 검증한다.

### 데이터와 API 명세 통합

- 저장 자료형, 학습 유형, 개인정보 역할, 보고서 정보영역을 분리한다.
- 문서 정보영역은 기존 요구대로 준식별자와 일반정보 두 가지를 유지한다.
- `apps/web/src/types/index.ts`와 `packages/contracts/src/index.ts`의 중복 정의를 없앤다.
- API 명세 기반 타입 생성과 CI 차이 검사를 도입한다. UI 전용 상태는 웹에 남긴다.
- 완료 기준: API 요청과 응답 변경이 타입 검사로 검출되고 단일/배치 옵션 전달이 일치한다.

### 전처리와 설문 검증 재사용

- 기존 `preprocessing/transformer.py`, `survey_logic.py`, `privacy/klt.py`를 재사용한다.
- 규칙 탐지, 사용자 승인, 규칙 검사, 값 보정을 서로 분리한다.
- 공백 정리와 명시적인 결측 표기를 공통 정책으로 관리하고 변경 개수를 기록한다.
- 학습되는 전처리는 홀드아웃 분리 후 훈련 데이터에만 fit한다.
- 완료 기준: 원본 파일 불변, 결정적 변환 재현, 검증 데이터 누출 방지, 규칙 미적용을 정상 통과로 오인하지 않음.

### 보고서 데이터와 렌더링 분리

- 공통 보고서 컨텍스트를 먼저 만들고 HWPX, HTML, Excel이 동일한 내용을 렌더링한다.
- 항목 설명, 생성 행 수, 평가 판정은 한 번만 계산한다.
- 설문 엔진 안의 Excel 보고서 작성은 exporter로 이동한다.
- 완료 기준: 한글 3종, HTML, Excel의 항목 설명과 측정값 일치. 기존 표 병합과 예시 행 수 회귀 테스트 통과.

### 화면 상태 분리

- `App.tsx`에서 업로드, 생성 요청, 작업 폴링을 기능별 훅으로 추출한다.
- 기존 다중 업로더와 상세 설정 컴포넌트를 재사용하고 파일별 설정은 분리한다.
- 완료 기준: 파일 전환, 작업 취소, 화면 이동 후 복귀 시 다른 파일의 설정이 섞이지 않는다.

## 3. 신규 기능 후보 (feat)

| 순서 | 기능 | 선행 조건 및 범위 |
| --- | --- | --- |
| 1 | 전처리 변경 미리보기 | 공통 명세 이후. 공백, 응답값 통일, 결측 표기별 변경 수와 승인 |
| 2 | 집단별 품질 평가 | 지역/성별/학교 유형 등 사용자 지정 집단의 분포 비교. 소표본은 별도 경고하며 원본 희귀값 노출 최소화 |
| 3 | 영속 작업 큐 | 공통 작업 서비스 이후. 프로세스 격리, 시간 제한, 재시도, 중복 실행 방지 |
| 4 | 부서별 인증·인가와 승인 | 작업, 원본, 산출물 전체에 접근제어. 담당자 승인과 감사 이력. 공유 서버 전환 시 우선순위 상향 |
| 5 | 동일 스키마 데이터 통합 | 검증된 세로 결합. 파일 출처와 스키마 충돌 기록. 응답자 연결키 자동 추정과 구분 |
| 6 | SQL 입력 커넥터 | 읽기 전용, 허용된 연결, 행 수 제한, 입력 스냅샷. S3와 REST는 별도 후속 커넥터 |
| 7 | 자연어 생성 규칙 | LLM이 검증 가능한 규칙 초안을 만들고 기존 생성 엔진이 실행. 원본 행의 외부 전송은 기본 금지 |

MICE/KNN, Isolation Forest, 정식 DP 생성 엔진은 데이터 특성과 요구사항이 생기면 별도 선택 기능으로 검토한다.
현재 범주형 설문에 기본 적용하거나 자동 이상치 삭제를 도입하지 않는다.

## 4. 정리 범위 (chore)

현재 상태: Git 및 Docker 제외 규칙은 반영했다. 실제 삭제 명령은 실행 환경 정책으로 차단되어 아래 임시 파일과 구형 캐시 폴더는 아직 디스크에 남아 있다.

이번 정리 대상은 참조되지 않는 다음 임시 산출물이다.

- `storage/test_batch_hwpx/`, `storage/test_*.hwpx`
- `apps/api/test_hwp_html.html/`
- `docs/test_survey_download.zip`, `docs/test_survey_logic_download.zip`
- 소스 없이 캐시만 남은 구형 `apps/api/app/`

다음 항목은 삭제하지 않는다.

- `apps/api/tests/`, `packages/synthetic_engine/tests/`, `tests/e2e/`: 실제 회귀 검증 코드
- `storage/templates/`: 운영 한글 템플릿
- 원본 데이터, 심의자료, 분석 문서, 최종 산출물, DB, 업로드 파일, 생성 이력
- `.uv`, `.venv`: 현재 실행 환경 확인 없이 제거하지 않음

이후 테스트 산출물은 pytest의 `tmp_path` 또는 `storage/temp/`를 사용한다.
운영 Docker 이미지에서는 테스트 코드와 임시 산출물을 제외하되 개발 저장소에는 회귀 테스트를 보존한다.

## 5. 권장 작업 단위

1. `chore`: 임시 파일 정리와 배포 제외 규칙 (제외 규칙 완료, 실제 파일 삭제 미완료)
2. `fix`: 파일 접근 제한과 평가 결과의 사실성
3. `fix`: 설문 결합, 미응답, 조건부 생성, 미작동 옵션
4. `refactor`: 공통 작업 및 결과 모델
5. `refactor`: 공통 명세, 전처리, 문서 렌더링, 화면 상태
6. `feat`: 위 표의 선행 조건이 충족된 기능부터 개별 추가

각 fix/refactor에는 재현 테스트를 함께 둔다. 실제로 중복되거나 더 이상 실행되지 않는 테스트만 검증 후 개별 삭제한다.
