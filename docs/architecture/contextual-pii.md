# 문맥 기반 인명 탐지

## 판정 순서

1. 도메인 화이트리스트와 문서 세션 제외 목록을 적용한다.
2. 기관 접미어로 기관명 구간을 먼저 제외한다.
3. 이름 필드의 `:`/`：` 또는 직책·호칭 문맥이 있는 2~4글자만 인명 후보로 삼는다.
4. Kiwi 상위 3개 분석에서 NNG/NNP 근거를 확인한다. NNP 또는 성씨만으로 인명을 추정하지 않는다. NNG 가능성은 NNP보다 우선 기록하되, 명시적인 이름 문맥은 허용한다.
5. 마스킹은 탐지된 정확한 구간만 바꾼다. 전역 치환 문서에서는 같은 표기가 문맥 밖에도 있으면 자동 제안을 보류한다.

Kiwi가 없어도 명시적인 문맥 규칙은 동작한다. 문맥 없는 이름, 외국 이름, 기관 접미어와 충돌하는 실제 이름은 누락될 수 있다. 신뢰도는 규칙 점수이며 보정된 확률이 아니다. 모든 문서의 오탐 0%, 재식별 불가능성 또는 법적 적합성을 보증하지 않는다.

## 도메인 화이트리스트

기본 파일: `storage/whitelist.json`. 배열 또는 다음 형태로 설정한다.

```json
{"words": ["도메인고유명칭"]}
```

환경변수 `SYNTHETIC_PII_WHITELIST_PATH`로 경로를 변경할 수 있다. 파일 변경은 재시작 없이 다음 검사부터 반영된다. 실제 개인정보를 등록하면 보호 대상에서 제외되므로 관리자가 검토해야 한다. 오류가 있는 설정은 조용히 무시하지 않는다.

`GET /api/v1/document-privacy/whitelist`는 읽기 전용이다. 일반 사용자 피드백으로 전사 제외 목록을 수정하지 않는다.

## 문서 세션 제외

- `POST /api/v1/document-privacy/{id}/ignored`: `{"word":"제외할값","action":"add"}` 또는 `remove`.
- `GET /api/v1/document-privacy/{id}/candidates`: 현재 설정과 세션 제외 목록으로 재검사.
- 휴지통은 서버 저장 성공 후 항목을 제거한다. 제외 해제 후 재검사하면 다시 제안된다.
- 제외 상태는 세션 디렉터리에 남아 서버 재시작 후에도 유지되며 다른 문서에는 적용되지 않는다.
- 제외된 값을 처리 API로 직접 제출해도 거절한다.

세션 ID는 인증을 대신하지 않는다. 사내 배포 시 기존 인증·인가 및 임시 원본/제외 목록의 보관·파기 정책을 별도로 적용해야 한다.

## 검증 범위

`test_contextual_pii.py`는 문맥, 기관 패턴, 복성, 외자, NNG 대안, Kiwi 부재, 설정 갱신, 마스킹 구간을 검증한다. `test_native_document_privacy.py`는 세션 격리·재검사·제외값 처리 차단을 검증한다. 자동 탐지가 놓친 값과 이미지 내 개인정보는 수동 검토가 필요하다.
