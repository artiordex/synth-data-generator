# 프로젝트 아키텍처

## 구조 요약

```text
apps/web                  React 18·TypeScript·Vite 기반 웹 화면
apps/api                  FastAPI 라우터와 작업 실행 서비스
packages/synthetic_engine 합성·평가·가명처리·문서 생성 핵심 엔진
packages/contracts        프런트엔드와 백엔드가 공유하는 타입·계약
storage                   업로드·산출물·임시 파일·SQLite 저장 영역
infra                     Docker·Nginx·Render 배포 설정
```

## 요청과 실행 흐름

1. 브라우저가 `apps/web`의 기능 화면에서 파일과 실행 옵션을 전송합니다.
2. `apps/api`가 입력을 검증하고 작업 ID를 만든 뒤 애플리케이션 서비스를 호출합니다.
3. 애플리케이션 서비스가 프로파일링, 합성 엔진, 평가, 문서 내보내기를 순서대로 조정합니다.
4. `packages/synthetic_engine`은 도메인 규칙과 알고리즘을 실행하고, 결과·지표·산출물 메타데이터를 반환합니다.
5. 결과는 `storage`에 저장되고 API가 상태·다운로드 경로·평가 정보를 웹 화면에 전달합니다.

## 계층별 책임

| 계층 | 위치 | 책임 |
| --- | --- | --- |
| 화면 | `apps/web/src` | 업로드, 옵션 입력, 진행 상태, 결과와 문서 보기 |
| API | `apps/api/src/synthetic_api/routes/v1` | HTTP 입력 검증, 인증·권한 경계, 응답 형식 |
| 애플리케이션 | `apps/api/src/synthetic_api/application` | 작업 실행, 취소, 이력, 배치 오케스트레이션 |
| 도메인 | `apps/api/src/synthetic_api/domain` | 작업·감사·결과 모델과 규칙 |
| 엔진 | `packages/synthetic_engine/synthetic_engine` | 프로파일링, 생성, 보호, 품질 평가, 내보내기 |
| 저장소 | `apps/api/src/synthetic_api/infrastructure` | SQLite, 파일 경계, 저장소 구현 |

## 데이터와 보안 원칙

- 원본 업로드와 생성 산출물은 `storage` 안에서 작업별로 격리합니다.
- 다운로드 경로는 저장소 루트 안으로 정규화하고 경로 순회 요청을 거부합니다.
- API는 Pydantic 계약으로 입력을 검증하고, 작업 이력에 실행 설정과 산출물 목록을 기록합니다.
- 프라이버시 평가는 미측정·실패를 성공으로 바꾸지 않으며, 결과 문서에도 상태를 그대로 표시합니다.
- 파일 변환과 문서 생성은 서비스 계층에서 조정하고, 알고리즘은 엔진 패키지에 둡니다.
