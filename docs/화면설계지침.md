# 사내 데이터 생성·보호 플랫폼 UI 지침

## 기본 원칙

- 화면 배경, 카드, 입력창, 테두리는 `apps/web/src/index.css`의 `--ui-*` 토큰을 사용한다.
- 주요 실행 동작은 파란색, 완료는 초록색, 주의는 주황색, 오류와 중단은 빨간색으로 표시한다.
- 장식용 그라데이션과 과한 그림자는 사용하지 않는다.
- 제목은 기능을 설명하는 짧은 한국어로 쓰고 영문 용어는 도움말이나 상세 설명에 둔다.
- 모든 작업 화면은 `소개 → 방식 또는 입력 → 설정 → 실행 → 결과` 순서를 따른다.

## 글씨 크기 표준 체계 (Typography Scale)

| 계층 (Level / Token) | 용도 (Usage) | 기준 크기 (px) | 행간 (Line Height) | 굵기 (Font Weight) | 추천 클래스 / 토큰 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Page Title (`text-2xl`)** | 워크스페이스 대제목, 히어로 타이틀 | `26px` | `34px` (1.3) | Bold (700) | `text-2xl font-bold tracking-tight` |
| **Section Header (`text-xl`)** | 주요 섹션 타이틀, 대형 패널 헤더 | `22px` | `30px` (1.36) | Bold (700) | `text-xl font-bold` |
| **Section / Group Title (`text-lg`)** | 서브 패널 헤더, 카드 타이틀, 모달 타이틀 | `18px` | `26px` (1.44) | SemiBold (600) / Bold | `text-lg font-bold` / `ui-section-title` |
| **Body Standard (`text-base`)** | 일반 설명문구, 안내글, 리포트 본문 | `16px` | `24px` (1.5) | Regular / Medium (400~500) | `text-base` / 기본 표준 본문 |
| **Control & Input (`text-sm`)** | 버튼, 폼 입력창(Input/Select/Textarea), 표 헤더 | `14.5px` | `22px` (1.5) | Medium / SemiBold (500~600) | `ui-field`, `ui-button`, `text-sm` |
| **Caption & Table Cell (`text-xs`)** | 도움말 문구, 데이터 표 셀, 보조 메타데이터, 툴팁 | `13px` | `18px` (1.38) | Regular / Medium (400~500) | `ui-help-text`, `ui-table td`, `text-xs` |
| **Badge & Micro (`text-2xs`)** | 상태 뱃지, 카운터 칩, 최소 상태 태그 | `12px` | `16px` (1.33) | SemiBold / Bold (600~700) | `ui-badge`, `text-2xs` (기존 9~11px 전면 폐지) |
| **Monospace / Code (`font-mono`)** | 코드 블록, 콘솔 로그, JSON/MD 뷰어, 파일 경로 | `12px ~ 14.5px` | `1.5` | Regular / SemiBold | `font-mono` (Consolas 적용) |

| 용도 | 사용 기준 |

## 화면 구성

1. 상단 앱 헤더에는 제품명, 사내용 표시, 테마, 용어사전, 이력, API 문서만 둔다.
2. 주 기능 탭은 가명데이터, 합성데이터, 더미데이터 순서를 유지한다.
3. 각 기능 첫 영역에는 동일한 작업 소개 컴포넌트를 사용한다.
4. 한 카드에는 한 가지 결정이나 한 단계의 작업만 배치한다.
5. 주요 실행 버튼은 카드 오른쪽 또는 하단 오른쪽에 배치한다.
6. 완료 화면에서도 다운로드 버튼은 주요 실행 버튼과 같은 파란색을 사용하고 완료 상태만 초록색으로 표시한다.

## 문구와 상태

- 버튼은 `파일 선택`, `관계 분석`, `합성 실행`, `결과 다운로드`처럼 동사로 끝낸다.
- 처리 중에는 현재 단계와 진행률을 함께 표시한다.
- 실패 시 사용자가 수정할 입력값이나 다시 실행할 단계를 명시한다.
- 전문 용어는 처음 한 번만 풀어 쓰고 이후에는 약어를 사용한다.

## 반응형 기준

- 2열 이상의 입력 영역은 작은 화면에서 1열로 바뀌어야 한다.
- 표는 셀을 압축하지 않고 가로 스크롤을 허용한다.
- 상단 탭의 표시 이름은 한국어로 유지해 좁은 화면에서도 잘리지 않게 한다.
- 터치 가능한 버튼과 선택 항목은 최소 36px 높이를 확보한다.
