# 최대 20개 파일 일괄 처리

단일 파일 합성 파이프라인·평가·HWPX 문서 생성·작업 이력을 재사용한다.
현재 저장된 소스와 Git 이력에서 기존 다중 파일 실행 진입점을 찾지 못해,
기존 기능 위에 일괄 접수와 순차 실행을 추가했다.

## 사용 순서

1. 합성데이터 업로드에서 최대 20개 파일을 함께 선택하거나 드래그한다.
   `파일 일괄 처리` 버튼으로도 진입할 수 있다.
2. 파일별 분석 결과·실패 사유를 확인하고 모델, 생성 행 수, 부서, 목적을 정한다.
   기본은 각 원본과 같은 행 수다. 공통 학습 설정과 파일별 컬럼 유형·결측 보존·평가 제외,
   파일별 심의자료 입력도 지원한다. 개별 설정이 공통 설정보다 우선한다.
3. 분석에 성공한 파일 개수를 확인하고 `N개 파일 일괄 실행`을 누른다.
4. 파일별 대기·처리·완료·실패·취소 상태를 확인한다. 완료된 파일은 개별 ZIP을 바로 받을 수 있다.
5. 전체 처리가 끝나면 `원본데이터_지역`, `합성데이터_지역`, `심의자료_지역`
   폴더와 `처리결과.json`이 포함된 전체 ZIP을 내려받는다.

## 처리 방식

- CSV, XLSX, XLS, TSV, TXT. 한 번에 최대 20개, 파일당 최대 100MB.
- 업로드마다 고유 저장 이름을 부여한다. 동명 파일도 서로 덮어쓰지 않는다.
  화면과 생성 문서에는 원래 파일명을 사용한다.
- 업로드·분석 실패는 파일별로 표시하고 실행에서 제외한다.
- 파일을 순서대로 처리한다. 20개 학습 모델을 동시에 메모리에 올리지 않는다.
  전체 ZIP 안의 파일명은 처리 순서 기준으로 `01.`, `02.`처럼 두 자리 번호를 붙인다.
  원본 파일명이 이미 `1. 데이터명_지역.xlsx` 형식이면 번호만 교체하고 나머지 이름은 유지한다.
  한 파일이 실패해도 다음 파일은 계속 실행한다.
- 대기 파일은 바로 취소한다. 실행 중인 파일은 파이프라인의 다음 취소 확인 지점에서 중단한다.
- 그룹과 파일별 이력은 SQLite에 저장한다. 브라우저를 닫아도 서버에서 처리가 계속되며,
  새로고침하면 같은 브라우저의 최근 그룹을 다시 조회한다.
- 서버 프로세스가 재시작되면 중단된 작업을 실패로 표시한다. 자동 재실행하지 않는다.
  Render의 현재 임시 저장소에서는 재배포 시 DB·업로드·산출물 보존은 별도 저장소 구성이 필요하다.

## API

- `POST /api/v1/datasets/upload-batch`: multipart `files`, 1~20개. 파일별 저장 이름·프로필·오류 반환.
- `POST /api/v1/batches`: `{"requests": [SynthesisRequest, ...]}`, 1~20개.
  업로드 응답의 `filename`을 `file_name`, `original_filename`을 같은 이름의 필드로 전달한다.
- `GET /api/v1/batches/{id}`: 전체 및 파일별 진행 상태, 개별/전체 ZIP 경로.
- `GET /api/v1/batches`: 최근 50개 일괄 작업과 파일별 상태 조회.
- `POST /api/v1/batches/{id}/cancel`: 실행 중·대기 중 작업 취소.
- 개별 취소·결과 조회·다운로드는 기존 작업 API를 사용한다.
  개별 작업 ZIP은 그대로 제공하고, 전체 일괄 ZIP은 제출용 폴더 구조로 평탄화한다.

검증: `uv run --locked --all-packages python -m pytest apps/api/tests/test_batch_synthesis.py`

## 통합 작업 이력

상단 `통합 작업 이력`에서 가명처리·더미데이터·AI 합성·일괄 작업을 최신순으로 조회한다.
각 화면의 최근 가명처리/더미데이터 이력 옆 링크는 해당 유형 필터로 통합 이력을 연다.
기존 이력 파일을 그대로 조회하므로 이전 기록도 함께 보인다. 가명처리와 더미데이터는
각각 최근 50건을 보관한다. 일괄 작업 묶음과 개별 합성 이력은 구분해서 표시하며,
`일괄 작업 열기`로 선택한 묶음의 진행 상황과 결과를 다시 확인할 수 있다.
